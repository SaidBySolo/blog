동기와 비동기를 처음 배울 때부터 지금까지, 저는 카페의 진동벨을 떠올리며 이해했습니다.

커피를 주문했는데 진동벨이 없다면 커피가 나올 때까지 카운터 앞에서 기다려야 합니다. 앞사람이 커피를 받아야 다음 사람도 주문할 수 있다면, 주문 하나가 오래 걸릴수록 뒤에 있는 사람들은 계속 기다리게 됩니다.

반대로 주문하고 진동벨을 받으면 카운터 앞에 서 있을 필요가 없습니다. 자리에 앉아 이야기를 나누다가 벨이 울릴 때 커피를 받으러 가면 됩니다.

커피가 더 빨리 만들어진 것은 아닙니다. 기다리는 시간을 다른 일에 쓸 수 있게 된 것입니다.

## 진동벨을 하나 받았을 뿐인데

프로그램도 일을 처리하다 보면 기다려야 하는 순간이 많습니다. 서버에 데이터를 요청하거나, 데이터베이스에서 결과를 가져오거나, 파일을 읽는 일이 그렇습니다.

동기 코드에서는 요청한 결과가 돌아올 때까지 다음 코드로 넘어가지 않습니다.

```python
coffee = order_coffee()
print(coffee)
```

`order_coffee()`가 끝나야 `print()`가 실행됩니다. 코드가 적힌 순서대로 움직이기 때문에 흐름을 이해하기는 쉽습니다.

하지만 커피를 만드는 동안 할 수 있는 일이 없다는 문제가 있습니다. 네트워크 응답을 1초 동안 기다려야 한다면, 프로그램도 그 자리에서 1초를 그대로 보낼 수 있습니다.

비동기 방식에서는 일단 작업을 맡겨 놓습니다. 작업이 끝날 때까지 다른 일을 처리하고, 완료되었다는 알림이 오면 원래 하려던 일을 이어 갑니다.

```text
주문하기 -> 진동벨 받기 -> 다른 일 하기 -> 벨이 울림 -> 커피 받기
```

여기서 중요한 것은 **비동기가 작업 자체를 빠르게 만들지는 않는다**는 점입니다.

커피 한 잔을 만드는 데 5분이 걸린다면 진동벨을 받아도 5분은 걸립니다. 다만 그동안 카운터 앞에 서 있지 않아도 됩니다. 비동기는 속도보다는 기다리는 방법에 대한 이야기입니다.

엄밀하게 들어가면 동기·비동기와 함께 블로킹·논블로킹도 구분해야 합니다. 지금 실행 중인 흐름이 기다림 때문에 멈춘다면 블로킹이고, 기다리지 않고 제어권을 돌려받는다면 논블로킹입니다.

두 개념을 완전히 같은 말로 볼 수는 없지만, 처음에는 카운터를 떠날 수 있는지를 생각하면 이해하기 편합니다.

## Node.js에서는 누가 진동벨을 보고 있을까

Node.js로 서버를 만들다 보면 JavaScript가 한 번에 하나의 일을 처리한다는 설명을 자주 듣습니다. 그렇다면 한 요청이 데이터베이스를 기다리는 동안 다른 요청은 어떻게 처리할 수 있을까요?

여기서 등장하는 것이 이벤트 루프입니다.

이벤트 루프는 완료된 작업이 있는지 확인하고, 실행할 수 있는 코드를 차례로 가져옵니다. 어떤 작업이 네트워크 응답을 기다리고 있다면 그 앞에 계속 서 있지 않고, 그동안 처리할 수 있는 다른 코드를 실행합니다.

JavaScript에서는 주로 Promise와 `async`/`await`로 이 흐름을 작성합니다.

커피가 완성되기를 기다리는 대신, 여기서는 카페의 주문 내역 파일을 읽는 상황으로 바꿔 보겠습니다.

```javascript
import { readFile } from "node:fs/promises";

async function main() {
  console.log("주문 내역을 읽기 시작합니다.");

  const orders = await readFile("coffee-orders.txt", "utf8");

  console.log(orders);
}

main();
```

`readFile()`은 파일을 모두 읽을 때까지 JavaScript 코드를 붙잡고 있지 않습니다. 나중에 결과를 받을 수 있는 Promise를 돌려줍니다.

`await`를 만나면 `main()`은 잠시 멈춥니다. 그렇다고 Node.js 전체가 멈추는 것은 아닙니다. 이벤트 루프는 다른 요청이나 콜백을 처리할 수 있고, 파일 읽기가 끝나면 `main()`의 나머지 부분을 다시 실행합니다.

진동벨에 빗대면 Promise는 나중에 결과가 생긴다는 약속이고, `await`는 벨이 울릴 때까지 이 주문의 다음 단계를 미뤄 두는 표현에 가깝습니다.

### 조금 더 깊이 들어가 보면, libuv

Node.js가 운영체제의 I/O를 직접 전부 처리하는 것은 아닙니다. 이벤트 루프와 비동기 I/O의 바탕에는 **libuv**라는 라이브러리가 있습니다.

libuv는 이벤트 루프뿐 아니라 네트워크, 파일 시스템, DNS, 타이머, 자식 프로세스처럼 프로그램 밖에서 일어나는 여러 작업을 다룹니다. 작업을 운영체제에 맡기고, 작업이 끝나면 그 결과를 다시 이벤트 루프로 가져옵니다.

운영체제마다 I/O가 끝났음을 알려 주는 방법은 조금씩 다릅니다. Linux에는 epoll, macOS와 BSD 계열에는 kqueue, Windows에는 IOCP가 있습니다. libuv는 이 차이를 감싸서 Node.js가 운영체제마다 완전히 다른 코드를 작성하지 않아도 되게 해 줍니다.

네트워크 작업을 예로 들면, 연결마다 스레드를 하나씩 만들어 응답을 기다리지 않습니다. 소켓에 읽을 데이터가 생겼는지 운영체제가 지켜보게 하고, 준비되었다는 알림이 오면 libuv가 이벤트 루프에 전달합니다. 카운터 직원이 제조대 앞에서 기다리는 대신, 커피가 완성되었을 때 진동벨로 알려 주는 방식입니다.

모든 작업을 이렇게 처리할 수 있는 것은 아닙니다. 파일 시스템이나 일부 DNS 작업처럼 같은 방식으로 기다리기 어려운 작업은 libuv의 스레드 풀이 대신 처리합니다. 일이 끝나면 그 결과만 이벤트 루프로 돌아옵니다.

그래서 “Node.js는 싱글 스레드다”라는 말만으로는 전체 모습을 설명하기 어렵습니다. JavaScript 코드를 실행하는 중심 흐름은 하나지만, 그 아래에서는 운영체제와 libuv의 작업 스레드가 함께 움직일 수 있습니다. 그렇다고 모든 코드가 여러 스레드에서 실행되는 것도 아닙니다. 이벤트 루프는 실행할 일을 하나씩 가져오고, 필요한 일부 작업만 바깥에 맡깁니다.

## Python에서는 코루틴으로 표현한다

Node.js에서는 이벤트 루프가 기다리는 작업들을 관리했습니다. Python에서도 같은 방식의 비동기 코드를 작성할 수 있는데, 이때 사용하는 것이 `asyncio`와 코루틴입니다. `async def`로 만든 함수를 코루틴 함수라고 부릅니다.

```python
import asyncio


async def order_coffee(name: str) -> str:
    await asyncio.sleep(1)
    return f"{name} 완성"


async def main() -> None:
    coffee = await order_coffee("아메리카노")
    print(coffee)


asyncio.run(main())
```

`order_coffee()`가 `asyncio.sleep()`을 기다리는 동안 코루틴은 실행권을 이벤트 루프에 돌려줍니다. 이벤트 루프는 다른 코루틴을 실행하다가 1초가 지나면 이 코루틴을 다시 이어서 실행합니다.

처음에는 `await`를 “끝날 때까지 기다린다”라고만 이해해서 조금 헷갈렸습니다. 기다린다면 동기 코드와 무엇이 다른지 잘 보이지 않았기 때문입니다.

차이는 **누가 기다리는가**에 있습니다. `await`를 만난 코루틴은 잠시 멈추지만, 이벤트 루프까지 함께 멈추는 것은 아닙니다. 한 손님은 진동벨을 들고 기다리고 있어도 카페는 계속 다른 주문을 받을 수 있습니다.

### 호출만 해서는 실행되지 않는다

일반 함수는 호출하면 바로 본문을 실행합니다. 하지만 코루틴 함수를 호출하면 먼저 코루틴 객체가 만들어집니다.

```python
async def order_coffee(name: str) -> str:
    return f"{name} 완성"


coffee = order_coffee("아메리카노")
print(coffee)  # "아메리카노 완성"이 아니라 coroutine 객체
```

이 코루틴은 `await`하거나 Task로 등록해야 이벤트 루프에서 실행됩니다.

여러 주문을 함께 처리하고 싶다면 `asyncio.gather()`를 사용할 수 있습니다.

```python
async def main() -> None:
    americano, latte = await asyncio.gather(
        order_coffee("아메리카노"),
        order_coffee("카페라테"),
    )

    print(americano)
    print(latte)
```

아메리카노를 다 받은 뒤 카페라테를 주문하는 것이 아니라, 두 잔을 먼저 주문하고 각각의 진동벨이 울리기를 기다리는 셈입니다.

## async를 붙였는데도 멈추는 이유

함수 앞에 `async`를 붙였다고 해서 그 안의 모든 코드가 알아서 비동기로 바뀌지는 않습니다.

```python
import time


async def order_coffee(name: str) -> None:
    time.sleep(3)
    print(f"{name} 완성")
```

`time.sleep()`은 현재 스레드를 3초 동안 멈춥니다. 이 코루틴이 실행되는 동안 이벤트 루프도 다른 코루틴을 처리하지 못합니다.

진동벨을 나눠 줬지만 정작 카운터 직원이 커피 머신 앞에 서서 기다리고 있는 것과 비슷합니다.

```python
async def order_coffee(name: str) -> None:
    await asyncio.sleep(3)
    print(f"{name} 완성")
```

`asyncio.sleep()`은 기다리는 동안 실행권을 돌려줍니다. 네트워크 요청이나 데이터베이스 접근도 마찬가지로 비동기를 지원하는 라이브러리를 사용해야 이벤트 루프를 막지 않습니다.

오래 걸리는 계산도 주의해야 합니다. `async` 함수 안에서 큰 숫자를 계속 계산하면 중간에 실행권을 돌려줄 지점이 없습니다. 이런 CPU 중심 작업은 별도의 스레드나 프로세스로 보내는 방법을 생각해야 합니다.

여기까지는 주로 코루틴의 입장에서 살펴봤습니다. 코루틴이 `await`에서 실행권을 돌려주면, 어떤 코루틴을 지금 실행할 수 있는지 확인하고 다시 깨워 주는 역할이 필요합니다. 그 역할을 맡는 것이 이벤트 루프입니다.

앞의 예제에서 사용한 `asyncio.run(main())`도 이 이벤트 루프를 준비하는 코드입니다. 이벤트 루프를 만들고 `main()` 코루틴을 실행한 뒤, 모든 작업이 끝나면 루프를 정리합니다.

## 이벤트 루프를 바꿔 보면

`asyncio.run()`은 보통 Python에 들어 있는 기본 이벤트 루프를 사용합니다. 대부분의 경우에는 이것만으로 충분하지만, 코루틴을 작성하는 방법과 이벤트 루프의 구현은 서로 분리되어 있습니다. 덕분에 코드는 그대로 두고 이벤트 루프만 다른 구현으로 바꿀 수 있습니다.

그 선택지 중 하나가 **uvloop**입니다.

비유를 이어 가자면 손님이 주문하는 방법과 진동벨은 그대로 두고, 주문을 확인하고 배분하는 카페의 주문 관리 시스템만 바꾸는 것에 가깝습니다. 이벤트 루프가 바뀌어도 앞에서 작성한 코루틴 코드는 그대로 사용할 수 있습니다.

### 왜 uvloop를 사용할까

이벤트 루프는 실행할 코루틴을 고르고, I/O가 끝났는지 확인하고, 멈춰 있던 작업을 다시 깨우는 일을 계속 반복합니다. 접속자가 많은 서버에서는 이 작은 작업도 아주 자주 일어나기 때문에, 이벤트 루프를 얼마나 효율적으로 구현했는지가 전체 성능에 영향을 줄 수 있습니다.

uvloop는 Cython으로 작성되었고 내부에서는 libuv를 사용합니다. Python의 기본 이벤트 루프보다 네트워크 I/O를 더 빠르게 처리하는 것을 목표로 만들어졌습니다. 그래서 동시에 많은 연결을 다루는 웹 서버나 네트워크 프로그램에서 자주 선택됩니다.

또 하나의 장점은 적용하기 쉽다는 점입니다. asyncio를 버리고 새로운 방식으로 코드를 작성하는 것이 아니라, 기존 코루틴 코드를 그대로 둔 채 이벤트 루프만 바꿀 수 있습니다.

다만 uvloop를 설치한다고 모든 프로그램이 빨라지는 것은 아닙니다. 동기 코드가 이벤트 루프를 막고 있거나 오래 걸리는 계산이 병목이라면 이벤트 루프만 교체해도 문제는 그대로 남습니다. 실제로 도움이 되는지는 적용 전과 후를 직접 측정해 보는 것이 가장 확실합니다.

### uvloop 사용하기

```bash
pip install uvloop
```

```python
import asyncio

import uvloop


async def main() -> None:
    await asyncio.sleep(1)
    print("완료")


uvloop.run(main())
```

기존의 `asyncio.run(main())` 대신 `uvloop.run(main())`을 사용했습니다. `async`, `await`, `asyncio.gather()` 같은 코드는 달라지지 않습니다.

uvloop는 내부적으로 libuv를 사용합니다. 앞에서 Node.js의 비동기 I/O를 설명할 때 등장했던 바로 그 라이브러리입니다. Node.js에서는 libuv가 런타임의 기본 구성 요소이지만, Python에서는 uvloop를 선택했을 때 asyncio의 이벤트 루프 아래에서 사용됩니다.

물론 libuv를 함께 사용한다고 Node.js와 Python이 똑같이 동작하는 것은 아닙니다. Promise와 코루틴이 실행되는 규칙은 각 언어와 런타임에 따라 다릅니다. 아래에서 I/O를 처리할 때 같은 기반 기술을 사용한다는 뜻에 가깝습니다.

## 마치며

Node.js와 Python은 비동기를 표현하는 방법이 조금 다르지만, 기다리는 동안 다른 일을 처리한다는 생각은 같습니다. Node.js에서는 Promise와 이벤트 루프가 이 흐름을 만들고, Python에서는 코루틴과 asyncio가 같은 역할을 합니다. uvloop는 여기서 Python의 이벤트 루프를 libuv 기반 구현으로 바꿀 수 있는 선택지입니다.

처음에 이야기한 진동벨처럼 비동기는 커피를 더 빨리 만드는 방법이 아닙니다. 커피가 완성될 때까지 카운터를 막지 않고, 그동안 다른 주문을 받을 수 있게 만드는 방법입니다.
